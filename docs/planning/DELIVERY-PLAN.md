## Work that can proceed independently

Organize evidence and source IDs, prepare corrections, maintain review ledgers, specify accessible interaction/navigation/media behavior, and resolve implementation choices once scope/design are confirmed. No need to ask the user to look up information already established in the inventory.

## Implementation sequence after review

1. Establish a private V2 source tree and repeatable build; preserve the untouched original baseline.
2. Implement normalized taxonomy, side/variant review rules and immutable-source traceability before UI rendering.
3. Build shared technique navigation/map/list views and old-route mappings.
4. Add saved stance, validated side-specific content, media lifecycle, print and accessibility.
5. Verify content completeness, source-link preservation, exceptions and responsive behavior.
6. Prepare a separate private/local review build, document findings, resolve failures and obtain explicit deployment approval.

A runnable prototype can precede the full build once the review proposal is accepted; deployment remains a separate decision. Do not mark existing issues complete because a specification or review ledger exists.

## Verification strategy — future implementation

Verify all 40 technique identities, five groups of eight, corrected category totals, valid target IDs and preservation of all source placements. Compare all right-sided source relationships and keep intentional deviations documented. Assert unreviewed left variants cannot render as approved content. Check left/right round trips, multiple arrows/sectors, bilateral options, text direction and label integrity, and unavailable/corrupt preference storage.

Exercise desktop and phone layouts, keyboard-only use, accessible names/focus/dialog dismissal, video playback and stop behavior, history/deep links, print layout and credits. Playback and rendered accessibility are still untested; metadata availability is not a substitute.

When an operator acceptance checklist is actually prepared, use the user's standing form-control/protection/color/result preferences and first confirm the test computer for that session. This planning document is not that checklist or a claim that tests passed.

## Release restriction

All work stays in lesthomassolutions/judo-gokyo-mind-maps-v2. No changes to original source, settings, deployment workflows, DNS or public website without explicit deployment authorization. Review artifacts must not be presented as a released replacement.
